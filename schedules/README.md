# 三个定时任务

这套系统的行为，一半在代码里，一半在**这四段提示词**里。

安装器不能替你建定时任务——它们存在 DSH 的 schedule 存储里，不是文件。所以流程是：装完重启，然后让 agent 按这里的模板建四个任务。

## 为什么不能自动建

DSH 的 schedule 是会话级状态，由 agent 通过 `schedule_create` 工具写入。外部脚本直接改存储文件会破坏它的状态一致性，所以这条路故意没走。

**代价**：装完你还差一句话。收益：不会写坏别人的 DSH。

## 怎么建

重启 DSH 后，把这句话发给 agent：

> 读 `{{READY_FILE}}`，里面是三个定时任务的完整提示词和触发时间，按它建好。

`install.mjs` 会把三份模板填好路径，生成到数据目录旁边的 `schedules-ready.md`。

## 四个任务是什么

| 任务 | 触发 | 作用 |
| --- | --- | --- |
| **早间提要** | 每天 08:00 | 今天几件事、最早几点；只读推送，不改账本 |
| **微信兜底扫描** | 每天 13:00 | 只在插件分诊失败时补漏；正常情况什么都不做、不发消息 |
| **晚间收口** | 每天 22:30 | 语义收尾：关任务、更新项目状态、发一屏对话 |
| **周报压实** | 周日 21:00 | 合并重复、改写四问、出周报 |

## 顺序不能反

早间提要（只读）→ 即时分诊（插件，秒级）→ 晚间收口（语义）→ 周报压实（结构）。早间提要只发不改，不参与下面的顺序约束。

**语义合并一定要放在晚间，不能提前。** 「这句话是在收尾上周那件事」需要理解上下文，正则做不到。把它塞进即时那层，就会出现「用户随口一句被当成新任务」——这个坑我们踩过。

## 想改

模板里用了两个占位符，安装时替换：

- `{{JOURNAL_DIR}}` — 数据目录
- `{{PYTHON}}` — Python 解释器绝对路径

想调时间，改 `<!-- schedule ... -->` 里那几行；想改行为，改正文。**改完重新生成一次** `schedules-ready.md`（重跑 `install.mjs` 即可），或者直接在 DSH 的定时任务面板里改。

## 一个提醒

如果 agent 建完发现没触发，先确认三件事：DSH 一直在运行（不是关着的）、时区是 `Asia/Shanghai`、任务状态是 `scheduled`。
